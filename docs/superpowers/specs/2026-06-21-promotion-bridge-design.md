# 승격 브리지 설계 (Track 1)

작성일: 2026-06-21
상태: 설계 확정, 구현 대기

## 한 줄 요약

섀도우 시뮬을 **시합장**으로 써서 설정 변종 여러 개를 동시에 겨루고,
**1등 설정을 "검증된 설정"으로 보관**한다. 진짜 계좌 모델을 만들 때 이 설정을 씨앗으로 쓴다.

## 배경 (현재 상태)

- 지금 운영 중인 건 **키움 모의투자 모델 1개**(실주문이 키움 모의 서버까지 감). 사용자는 이걸 "연습계좌"라 부름.
- **진짜 계좌(51342627)는 아직 모델 없음.** 나중에 만들 예정.
- Track 1에서 **섀도우 시뮬**을 이미 만듦: 키움에 주문을 안 보내고 "샀다 치고" 합성 체결만 계산 → 돈 0원, 무제한 병렬 가능.
  - `ShadowKiwoomService`(주문/잔고만 가로챔), `SimulationService.runSimCycle`(원본 모델 1:1 클론 1개 실행), perf row에 `simulated/sim_source/sim_run_id` 기록.
- 한계: 모의투자는 주문이 키움까지 가서 **설정 1개**밖에 못 돌림. 섀도우는 합성 체결이라 **설정 N개 동시** 가능 → 시합장으로 적합.

## 목표 / 비목표

**목표**
- 챔피언(현 모의투자 설정)에서 파생한 설정 변종들을 섀도우에서 동시에 돌려 채점한다.
- 1등 설정을 별도 보관해, 추후 진짜 계좌 모델의 시작 설정으로 쓸 수 있게 한다.

**비목표 (이번엔 안 함)**
- 진짜 계좌 모델 자동 생성/적용 — 항상 사용자 수동.
- 운영(모의투자) 모델에 자동 write-back — 안 함.
- 워커 자동 스케줄 — 별도 Track 1 항목. 이번엔 트리거(수동/엔드포인트)만.
- AI 기반 변종 생성(Track 2) — 이번엔 기계적 변형만.

## 부품 4개

### ① 변종 생성기 (variant generator)

챔피언 settings를 복사해, 손잡이 몇 개만 단계적으로 바꾼 변종 settings 목록을 만든다.

- 변형 손잡이 4개:
  - `minAiConfidence` — 살 때 까다로움
  - `defaultPositionSize` — 한 번에 얼마
  - `stalePeriodDays` — 얼마나 오래 들고 있나
  - `surgeThreshold` — 급등 시 더 버티기
- 변종 개수: **5개** (챔피언 1 + 도전자 4). 처음엔 작게, 나중에 늘릴 수 있게 상수화.
- 변형 폭은 작게(예: ±한 단계). 챔피언 자신도 한 변종으로 포함해 기준선 역할.

### ② 시합 실행 (race runner)

변종마다 별도 **섀도우 시뮬 모델**을 만들어 같은 후보 종목으로 `runSimCycle`을 돌린다.

- `SimulationService`를 확장: 지금은 원본당 sim 모델 1개(정확한 클론)만 만듦.
  변종 id별로 sim 모델을 구분 생성하고(`config.variantId`), **변종 settings를 덮어쓴다**.
- 한 시합 배치는 공통 `simRunId`(또는 배치 id)로 묶어 나중에 묶어서 채점.
- 시합은 시간이 걸린다(사서 → 나중에 팖). 한 번 실행이 아니라 **여러 사이클 누적**으로 성과가 쌓인다.

### ③ 채점 (scoring)

변종별 `simulated=true` perf row를 모아 점수를 낸다.

- 점수 = 수익률(누적 profitLossRate) + 승률(isWin 비율).
- **최소 거래 수 미달 변종은 후보에서 제외**(운빨 1등 방지). 기본 최소값은 상수로.
- 1등 = 최소 거래 수를 채운 변종 중 최고점.

### ④ 승격 = 보관 (promotion record)

1등 변종의 settings를 **"검증된 설정"으로 따로 저장**한다.

- 저장 위치: 검증된 설정 스냅샷(설정 값 + 점수 + 시합 배치 id + 일시). 신규 테이블 또는 기존 구조 재사용은 구현 계획에서 확정.
- **자동 적용 없음.** 운영 모델/진짜 계좌에 쓰지 않는다.
- 추후 사용자가 진짜 계좌 모델을 만들 때, 이 스냅샷을 시작 설정으로 불러올 수 있게 한다(불러오기 UI/엔드포인트는 후속).

## 안전 가드 (불변)

- 섀도우 경로만 사용 → 실주문 0건, 실계좌·모의투자 운영 모델 무영향.
- 승격은 **보관까지만**. 실제 적용은 항상 사용자 손으로.
- 시뮬 거래는 `simulated=true`로 실거래 학습과 분리(기존 보장 유지).

## 성공 기준

1. 변종 5개로 시합 배치를 트리거하면, 섀도우 sim 모델 5개가 만들어지고 각자 다른 settings로 돈다.
2. 시뮬 거래가 변종별로 구분되어 쌓인다(`simulated=true`, 변종 식별 가능).
3. 채점이 변종별 점수를 내고, 최소 거래 수 가드가 동작한다.
4. 1등 설정이 "검증된 설정" 스냅샷으로 저장된다.
5. 실주문 0건 — 안전 가드 회귀 통과.
