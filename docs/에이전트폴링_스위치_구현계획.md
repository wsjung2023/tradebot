# 에이전트 폴링 ON/OFF 스위치 + 실시간 현황 — 구현 계획

작성일: 2026-04-12

---

## 목적

- 개발/운영 각각 독립적으로 에이전트 폴링을 켜고 끌 수 있는 스위치
- 설정 화면에서 현재 상태(연결됨/끊김, 오늘 요청 횟수)를 실시간으로 확인
- 비용 발생 여부를 직접 통제

---

## 핵심 설계 결정

### 왜 DB 저장이 아닌 서버 메모리 저장인가?
- 개발 서버(spock.replit.dev)와 운영 서버(mainstop3.replit.app)가 **같은 DB를 공유**
- DB에 저장하면 하나를 끄면 양쪽 다 꺼짐 → 불편
- 서버 인스턴스별 메모리 변수로 저장하면 개발/운영 **완전 독립**
- 서버 재시작 시 기본값(ON)으로 돌아옴 → 예측 가능한 동작

## 수정 파일 목록

### 1. `server/routes/kiwoom-agent.routes.ts`

**추가할 변수:**
```typescript
let _pollingEnabled = true;        // ON/OFF 스위치 (서버별 독립)
let _todayJobCount = 0;            // 오늘 처리된 잡 수 (메모리)
```

**수정할 엔드포인트:**
- `GET /api/kiwoom-agent/jobs/next`
  - `_pollingEnabled === false` 이면 즉시 `{ job: null }` 반환 (touchAgentSeen 호출 안 함)

**추가할 엔드포인트:**
- `GET /api/kiwoom-agent/polling-status` (인증 필요)
  - 반환: `{ enabled, isAgentActive, agentLastSeenSecondsAgo, todayPollCount, todayJobCount }`
- `POST /api/kiwoom-agent/polling-switch` (인증 필요)
  - 입력: `{ enabled: boolean }`
  - 반환: `{ enabled }` (변경 후 상태)

## 예상 동작 시나리오

1. 서버 시작 → 폴링 **ON** (기본값)
2. 개발 중 비용 절약 원할 때 → 설정 화면에서 **OFF** 클릭
3. 에이전트가 계속 연결해도 잡을 받지 못함 → 비용만 최소 수준
4. 테스트할 때 → **ON** 클릭 → 즉시 정상 작동
5. 서버 재시작(배포) → 자동으로 **ON** 복귀 (재시작 = 새 배포 = 쓸 준비 됐다는 뜻)

## 비용 영향

OFF 상태일 때:
- 에이전트 폴링 요청 자체는 옴 (에이전트가 모름)
- 서버는 즉시 `{ job: null }` 반환 (DB 쿼리 없음, 1ms 미만)
- Autoscale 비용: 사실상 0에 수렴
