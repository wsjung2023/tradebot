# 수정변경 작업계획서

작성일: 2026-05-07  
대상 프로젝트: `tradebot`  
목적: 현재 구현된 자동매매 로직을 사용자가 원하는 "후보선정 강화 + 5단계 분할매수 + AI 재량 추가매수/청산 + winRate 기반 전략 진화" 구조로 전면 정렬한다.

---

## 1. 결론 요약

현재 코드는 자동매매의 뼈대는 있으나, 실제 라이브 경로는 아직 아래와 같은 한계가 있다.

1. 후보종목은 찾지만 `모멘텀/거래량/우량성/이슈/세력성`을 구조적으로 분리 평가하지 않는다.
2. 실전 진입은 사실상 `currentLine <= 50` 규칙형에 가깝다.
3. 추가매수는 `entryLine - 10` 규칙으로만 동작하며, AI가 "이번엔 1유닛/2유닛/대기"를 고르지 않는다.
4. 매도는 익절/손절/동적청산 규칙형이 중심이고, AI가 `보유/부분매도/전량매도`를 유연하게 결정하지 않는다.
5. 학습은 일부 가중치와 임계치만 조정하며, 라더/유닛/청산 정책까지 진화시키지 않는다.
6. `모델 유형`은 현재 생성 UI에 있으나 실전 자동매매 로직에서 거의 전략 차이를 만들지 않는다.
7. 손절은 사실상 기본 전제로 노출되는데, 사용자가 원하는 뒷차기 방식에는 맞지 않는다.

따라서 이번 변경은 단순 튜닝이 아니라 **실제 라이브 매매 경로와 설정 구조를 전략 중심으로 재구성하는 작업**이다.

---

## 2. 목표 상태

최종 목표 로직은 아래 순서로 동작해야 한다.

1. 조건검색식으로 후보를 수집한다.
2. 후보마다 `모멘텀`, `거래량`, `우량성`, `이슈/테마`, `급등주/세력주 성격`, `DART 위험도`를 정규화된 점수로 계산한다.
3. AI는 위 점수와 차트/뉴스/재무를 종합해 `매수대상 여부`, `종목 성격`, `초기 진입 라인`, `라인별 유닛`, `하위 라인 2유닛 투입 여부`, `최대 보유 유닛`, `보유 중 관리 전략`을 결정한다.
4. 매수는 `초록/파랑/남색/보라/연보라` 5개 라인 기준으로 진행하되, 기본은 1라인 1유닛, 필요 시 AI가 특정 하위 라인에 2유닛을 배정할 수 있어야 한다.
5. 종목당 총투입금은 `baseUnitSize * maxUnitsPerStock` 하드캡으로 강제한다.
6. `모델 유형`은 단순 라벨이 아니라 실제 전략 프로파일이어야 하며, 후보선정 가중치/진입 성향/청산 성향에 직접 반영되어야 한다.
7. 매도는 단순 익절/손절이 아니라 `부분익절`, `추세연장 보유`, `하위 라인 재진입 대비 현금확보`, `손실 확정`, `급등 과열 청산` 중 AI가 결정하되, 위험 상한은 룰로 막는다.
8. 손절은 기본 강제가 아니라 전략 옵션이어야 하며, `손절 사용 안 함`, `약한 손절`, `강한 손절`, `AI 우선 + 최종 안전장치만 유지` 같은 형태로 선택 가능해야 한다.
9. 학습은 `winRate`뿐 아니라 `expectancy`, `profit factor`, `라인별 성과`, `유닛 배치 패턴`, `AI 보유판단 성과`까지 학습해 설정에 반영한다.

## 3. 현재 코드와 목표의 핵심 차이

| 항목 | 현재 구현 | 목표 구현 |
|---|---|---|
| 후보 선별 | 조건검색 + AI confidence + 재무/유동성/DART | 조건검색 + 다축 점수화 + AI 종목 성격 분류 |
| 모델 유형 | 저장만 되고 실전 차이 거의 없음 | 전략 프로파일로 실제 로직 차이 발생 |
| 진입 조건 | `currentLine <= 50` | AI 승인 + 5라인 계획 + 자금/리스크 검증 |
| 라인별 유닛 | 정적 `lineUnits` | 기본 정적 + AI 동적 override |
| 추가매수 | `entryLine - 10` | 다음 미체결 라인 도달 + AI 재판단 |
| 종목당 상한 | 설정상 유사하나 강제 아님 | 하드캡 강제 |
| 손절 | 초록/파랑 CL + 손실률 도달 시 규칙형 발동 | 사용 여부 선택 + AI 우선 판단 + 최종 안전장치 |
| 매도 | 익절/손절/동적청산, 사실상 전량 | 부분익절/보유/전량청산 혼합 |
| 학습 | 가중치/임계치 일부 조정 | 라더/유닛/청산 정책까지 개선 |

## 5-C. AI 서비스 확장

### C-0. `modelType`를 실제 전략 프로파일로 승격

- 파일:
  - `shared/schema.ts`
  - `client/src/components/auto-trading/AutoTradingModelDialog.tsx`
  - `client/src/pages/auto-trading.tsx`
  - `server/services/trade-executor.service.ts`
  - `server/services/ai.service.ts`

- 현재 문제:
  1. 생성 UI에서 `모멘텀 / 가치투자 / 기술적분석 / 커스텀`을 선택하게 하지만 실전 엔진에서는 전략 차이가 거의 없다.
  2. 사용자 입장에서는 "중요한 전략 선택"처럼 보이는데, 실제론 분류값에 가깝다.

- 변경 목표:
  1. `modelType`을 단순 라벨이 아니라 실제 전략 preset으로 바꾼다.
  2. 선택한 유형이 후보선정 가중치, 진입 성향, 추가매수 성향, 청산 성향에 반영되게 만든다.

- 유형별 최소 의미 정의:
  1. `momentum`
     - 모멘텀/거래량/이슈 가중치 높음
     - 강한 종목 추종형
     - 손절 허용 가능성 상대적으로 높음
  2. `value`
     - 우량성/재무/저평가 가중치 높음
     - 보수적 분할매수
     - 손절은 약하거나 비활성 가능
  3. `technical`
     - 레인보우 라인/추세/거래량 패턴 비중 높음
     - 시그널 진입 엄격
  4. `custom`
     - 사용자가 모든 정책을 직접 조정

- 구현 방식:
  1. 모델 생성 시 `modelType`별 preset 자동 주입
  2. preset이 아래를 채우도록 함
     - `candidateScoringWeights`
     - `candidateThresholds`
     - `entryLadderSettings`
     - `stopLossPolicy`
     - `aiExitPolicy`
  3. 사용자가 세부값을 수정하면 `customized from preset` 상태를 표시

- UI 설명 문구 추가:
  - `모멘텀`: 강한 종목을 빠르게 추종하는 전략
  - `가치투자`: 우량성과 가격 메리트를 우선하는 전략
  - `기술적분석`: 차트와 거래량 신호를 엄격히 따르는 전략
  - `커스텀`: 모든 기준을 직접 조정하는 전략

### F-1-1. 손절은 "필수 기능"이 아니라 "선택 가능한 정책"으로 변경

- 파일:
  - `shared/schema.ts`
  - `client/src/components/auto-trading/AutoTradingModelDialog.tsx`
  - `client/src/components/auto-trading/AutoTradingSettings.tsx`
  - `server/services/trade-executor.service.ts`

- 현재 문제:
  1. 모델 생성 UI가 손절값 입력을 사실상 기본 전제로 두고 있다.
  2. 현재 런타임도 `stopLossConfig`가 있으면 조건 충족 시 기계적으로 손절한다.
  3. 하지만 사용자가 원하는 뒷차기 방식은 손절보다 분할관리와 복원 판단이 더 중요하다.

- 변경 목표:
  1. 손절 사용 여부를 켜고 끌 수 있게 한다.
  2. 손절을 아래 모드로 나눈다.

```ts
stopLossMode:
  'disabled'
  'soft_ai_first'
  'conditional'
  'hard'
```

- 모드 의미:
  1. `disabled`
     - 일반 손절 사용 안 함
  2. `soft_ai_first`
     - 손실 상태에서도 즉시 손절하지 않고 AI가 먼저 `hold / scale_in / partial_sell / full_sell` 판단
  3. `conditional`
     - CL 구간 + 손실률 + 거래량 악화 + 이슈 악화 등 복합조건형
  4. `hard`
     - 지정 조건 도달 시 기계적 손절

- 뒷차기 기본 원칙:
  - 뒷차기형 프로파일 기본값은 `disabled` 또는 `soft_ai_first`로 설계

- 최종 안전장치:
  1. 거래정지성 급위험 공시
  2. 계좌 일일 손실 상한
  3. 재난 수준 급락
  4. 시스템 차원의 강제 리스크 컷

## 10. 최종 판단

이번 변경의 핵심은 "AI 점수 몇 개 더 추가"가 아니다. 실제로는 아래 4가지를 같이 바꾸는 작업이다.

1. 후보 평가 구조
2. 진입/추가매수/청산 실행 구조
3. 학습이 반영되는 파라미터 범위
4. 사용자가 보는 설정 UI와 실제 엔진 동작의 일치

이 4개를 같이 바꾸지 않으면, UI만 그럴듯하고 실제 라이브 매매는 지금처럼 규칙형에 머문다.  
따라서 구현은 반드시 `schema -> storage -> executor -> worker -> learning -> UI` 순서로 진행해야 한다.
