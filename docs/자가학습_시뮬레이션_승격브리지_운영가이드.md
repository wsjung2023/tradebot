# 자가학습: 전방 섀도우 시뮬레이션 + 승격 브리지 (운영자 가이드)

작성: 2026-06-21 · 대상: 운영자/관리자 · 상태: 백엔드 API 제공 (전용 UI 미구현)

자가학습 로드맵 Track 1의 산출물. 목적은 **돈 안 쓰고(실주문 0) 설정을 실험·검증해서, 검증된 좋은 설정을 진짜 계좌 모델의 씨앗으로 보관**하는 것.

---

## 1. 한눈에 보기

```
지금 모의투자 모델 (챔피언)
        │
        ▼  설정 변종 여러 개를 섀도우 시뮬에서 동시에 "샀다 치고" 시합 (실주문 0)
        ▼
변종별 채점 (수익률 + 승률, 최소 거래 수 가드)
        ▼
1등 설정 → proven_settings 테이블에 보관 (운영 모델 자동 적용 안 함)
        ▼ (나중에 사용자가)
진짜 계좌 모델 만들 때 이 설정을 시작점으로 사용
```

## 2. 안전 보장 (불변)

- **실주문 0건.** 모든 시뮬 경로는 `ShadowKiwoomService`를 거친다 — 시세/차트 "읽기"는 실제 키움 REST를 쓰되, **주문(placeOrder/cancelOrder)은 가로채 합성 체결만 반환**한다. 실제 키움 주문 API를 절대 호출하지 않는다.
- **운영 모델 무변경.** 시뮬은 별도 시뮬 모델/계좌에서만 돌고, 1등은 *보관*까지만. 운영/실계좌 모델 설정을 자동으로 바꾸지 않는다.
- **학습 격리.** 시뮬 거래는 `trading_performance.simulated = true`로 기록 → 실거래 학습과 분리.
- 워커(`auto-trading-worker`)는 `isSimulation` 모델을 실행 대상에서 제외(방어선).

## 3. 구성 요소

| 요소 | 파일 | 역할 |
|---|---|---|
| 섀도우 키움 | `server/services/shadow-kiwoom.service.ts` | 주문/잔고만 합성, 읽기는 실제 |
| 시뮬 오케스트레이션 | `server/services/simulation.service.ts` | 시뮬 모델/계좌 생성, 사이클 실행, 시합·정산 |
| 변종 생성기 | `server/services/variant-generator.ts` | 챔피언 설정에서 손잡이 하나씩 바꾼 변종 5개 |
| 채점 | `server/services/race-scoring.ts` | 변종별 점수 + 1등 선정(최소 거래 수 가드) |
| 보관소 | 테이블 `proven_settings` (마이그레이션 0017) | 1등 설정 스냅샷 |

**변종 손잡이 4개**: `minAiConfidence`(살 때 까다로움), `defaultPositionSize`(한 번에 얼마), `stalePeriodDays`(보유 기간), `surgeThreshold`(급등 시 버티기). 챔피언(변형 없음) + 도전자 4개 = 기본 5개.

## 4. 사용법 (API)

모두 인증 + 모델 소유권 필요. `modelId`는 **챔피언(원본, 비-시뮬) 모델 id**.

| 엔드포인트 | 동작 |
|---|---|
| `POST /api/auto-trading/simulation/run` `{ modelId }` | 단일 시뮬 1사이클 (원본 1:1 클론) |
| `POST /api/auto-trading/simulation/race/run` `{ modelId, count? }` | **시합 1사이클** — 변종 `count`개(기본 5)를 각각 섀도우로 1회. **반복 호출로 성과 누적.** |
| `POST /api/auto-trading/simulation/race/settle` `{ modelId, minTrades? }` | **정산** — 변종 채점 → 1등을 `proven_settings`에 보관. `minTrades`(기본 3) 미만이면 후보 제외. |

## 5. 워크플로우

1. 챔피언 모델에 **신선한 후보 종목**(1시간 이내 스캔)이 있어야 시뮬이 실제 평가를 한다. 없으면 `evaluated=0`(플럼빙만 동작).
2. `race/run`을 **여러 번** 호출해 변종별 시뮬 거래를 누적시킨다. (장중 반복 권장 — 워커 자동 스케줄은 아직 미구현.)
3. 충분히 쌓이면 `race/settle` 호출 → 1등 설정이 `proven_settings`에 저장된다.
4. 진짜 계좌 모델을 만들 때 이 설정을 시작점으로 사용. (불러오기 UI는 후속.)

## 6. 현재 제약 (후속 과제)

- **전용 UI 없음** — 위 엔드포인트는 API/관리자 트리거. 화면은 후속.
- **워커 자동 스케줄 미구현** — `race/run`을 수동/외부 스케줄로 반복해야 누적됨.
- **proven_settings 불러오기 UI 없음** — 보관까지만. 진짜 모델에 적용은 수동.
- 시뮬 시세 읽기는 실제 키움 REST 인증 필요 — 계좌 키가 유효해야 분석이 돈다.

## 7. 관련 (Track 0: LLM provider)

분석 LLM은 `LLM_PROVIDER` 환경변수로 결정(기본 OpenAI 유지, Claude/로컬 옵션 추가 가능). 시뮬도 동일 경로 사용. 자세한 건 `server/services/llm-provider.ts`.
