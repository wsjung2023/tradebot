## Phase 1. 에이전트 제거 (Agent-less 아키텍처)

### 목표
`kiwoom-agent.py` 없이 서버(Node.js)가 직접 키움 REST API 토큰을 관리.
배포용 멀티유저 앱 전환의 전제조건.

### 현황
- `kiwoom.base.ts`에 `_doAuthenticate()` 이미 구현됨
- 에이전트는 토큰 관리 + `token_cache.json` 저장만 담당
- 서버는 이미 키움 REST API 직접 호출 중

### 작업 항목
1. **토큰 자체 발급/갱신** (`kiwoom.base.ts`)
   - `_doAuthenticate()` 그대로 사용
   - 만료 1시간 전 자동 갱신 스케줄러 추가 (`setInterval`)
   - DB 또는 파일에 토큰 저장 (멀티 인스턴스 대비)

2. **에이전트 캐시 의존성 제거**
   - `ensureValidToken()` 내 `agent/token_cache.json` 읽기 로직 제거
   - 5분 polling `setInterval` 제거
   - 401 인터셉터는 유지 (직접 재인증으로 변경)

3. **Task Scheduler 정리**
   - `TradeBot-Agent` 스케줄 제거
   - `restart-all.bat` 에이전트 관련 항목 제거
   - `CLAUDE.md` 운영 규칙 업데이트

4. **멀티유저 대비 (배포용)**
   - 유저별 appKey/appSecret DB 저장
   - 유저별 토큰 인스턴스 분리 (현재 싱글톤 → 유저별 KiwoomService)

### 예상 작업량
- 소~중 (2~3시간)
- 위험도: 낮음 (이미 서버가 직접 호출 중)

## Phase 2. 종목 상태 필터링 (orderWarning / state / auditInfo)

### 목표
키움 `ka10075` 응답의 투자경고/위험/환기 정보를 종목검색기 실행 시 함께 수집하여
매수 후보 필터링 및 AI 점수에 반영. 모델별 세팅으로 조정 가능.

### API
- 엔드포인트: `GET /api/dostk/stkinfo` (ka10075)
- 응답 필드:
  - `orderWarning`: 0=정상, 3=단기과열, 4=투자경고, 5=투자위험
  - `state`: 파이프 구분 문자열 (예: `"상한가20%|담보부족|신용가능"`)
  - `auditInfo`: 감사정보 (예: `"정기감사환기종목"`)

### DB 스키마 (`stock_status` 테이블)
```sql
stock_code        VARCHAR(10) PRIMARY KEY
order_warning     SMALLINT    -- 0/3/4/5
state             TEXT        -- 파이프 구분 원본
audit_info        TEXT
is_warning        BOOLEAN     -- orderWarning >= 3
is_danger         BOOLEAN     -- orderWarning = 5
is_audit_alert    BOOLEAN     -- auditInfo에 "환기" 포함
credit_available  BOOLEAN     -- state에 "신용가능" 포함
updated_at        TIMESTAMP
```

### 갱신 시점
- **종목검색기 실행 시 해당 종목만 함께 조회·저장** (별도 스케줄 없음)
- 검색기 → ka10075 호출 → stock_status upsert → 필터 적용

### UI 표시
- 종목검색 결과 및 후보 종목 목록에 뱃지 표시
  - 🔴 `투자경고` (orderWarning=4)
  - 🚨 `투자위험` (orderWarning=5)
  - ⚠️ `환기종목` (auditInfo에 "환기" 포함)
  - 🔥 `단기과열` (orderWarning=3)

### 모델 설정 (AutoTradingSettings)
- **전체 ON/OFF** 토글
- **시그널별 반영 여부** 개별 토글 (단기과열 / 투자경고 / 투자위험 / 환기)
- **점수 차감값 조정**: 시그널별 -5 ~ -30점 슬라이더
- **하드 차단 vs 점수 차감** 선택: 차단이면 후보 자체 제외, 차감이면 점수만 깎음

### 학습 연동
- `trading_performance`에 매수 시점의 `order_warning`, `state` 스냅샷 저장
- 승률/수익률 분석 시 "어떤 경고 상태의 종목이 빠른 수익을 냈는지" 패턴 추출
- 학습 결과로 시그널별 차감 점수 자동 조정 제안 (모델 설정에 반영)

### 작업 항목
1. `stock_status` 테이블 migration
2. 종목검색기 실행 시 ka10075 조회·upsert 서비스 함수
3. `evaluateCandidateStock()` 필터/점수 반영 (모델 설정 기반)
4. AutoTradingSettings UI — 시그널 설정 섹션 추가
5. 종목 목록/후보 화면 뱃지 표시
6. `trading_performance` 매수 시 상태 스냅샷 저장
7. 학습 분석 쿼리 — 경고 상태별 승률/평균 보유기간 집계

### 예상 작업량
- 중 (4~5시간)

## Phase 3. 매수/매도 시점 캔들 데이터 수집 + 패턴 학습

### 목표
실제 매수·매도 시점의 OHLCV + 보조지표 스냅샷을 저장하여,
"빠른 수익(빠른 승리)"을 낸 케이스의 캔들 패턴을 추출하고 매수 타이밍에 활용.

### 핵심 개념
- 매수 시점의 캔들 상태(이동평균 위치, 볼린저 위치, 거래량 등)를 저장
- 매도 시점(청산)의 수익률·보유기간과 함께 기록
- 데이터가 쌓이면 **"짧은 보유기간 + 높은 수익률"** 케이스의 공통 패턴 자동 추출
- 추출된 패턴을 종목검색기/AI 점수에 반영 → 빠른 반등 종목 우선 포착

### DB 스키마

**`trade_candle_snapshot` 테이블** (매수/매도 시점 스냅샷)
```sql
id                SERIAL PRIMARY KEY
performance_id    INTEGER REFERENCES trading_performance(id)
stock_code        VARCHAR(10)
snapshot_type     VARCHAR(4)   -- 'BUY' / 'SELL'
snapshot_date     DATE
-- OHLCV
open              INTEGER
high              INTEGER
low               INTEGER
close             INTEGER
volume            BIGINT
-- 이동평균 (일봉 기준)
ma3               NUMERIC
ma7               NUMERIC
ma20              NUMERIC
ma60              NUMERIC
ma120             NUMERIC
ma240             NUMERIC
-- 볼린저밴드 (20일)
bb_upper          NUMERIC
bb_mid            NUMERIC
bb_lower          NUMERIC
bb_position       NUMERIC      -- 0~1: 밴드 내 현재가 위치
-- 시그널
is_golden_cross   BOOLEAN      -- 단기선 장기선 상향돌파 여부
volume_ratio      NUMERIC      -- 전일 거래량 대비 배율
rainbow_line      SMALLINT     -- 매수 시점 레인보우 라인
created_at        TIMESTAMP
```

### 수집 시점
- **매수 주문 실행 직후**: `executeBuy()` 내에서 해당 종목 일봉 250개 조회 → 지표 계산 → BUY 스냅샷 저장
- **매도 청산 직후**: `executeExitSell()` / `executeSell()` 내에서 SELL 스냅샷 저장
- 일봉 데이터는 `getStockChart('D', 250)` 이미 호출 중 → 추가 API 호출 최소화

### 패턴 학습 분석

**학습 조건**: `trading_performance`에서 `isWin=true` + `보유기간 N일 이하` 케이스 추출

**분석 항목**:
- 매수 시 볼린저 위치 분포 (하단 근처일수록 반등 빠름?)
- 매수 시 거래량 배율 분포
- 매수 시 골든크로스 여부
- 매수 시 레인보우 라인별 평균 보유기간/수익률

**출력**:
- 빠른 승리 확률이 높은 패턴 조합 → `fast_win_score` (0~100)
- 종목검색기에서 `fast_win_score` 기준 정렬/필터 제공
- AI 분석 입력에 현재 종목의 캔들 패턴 요약 포함

### 작업 항목
1. `trade_candle_snapshot` 테이블 migration
2. `TechnicalIndicators` 클래스 (MA, 볼린저, 골든크로스 계산)
3. `executeBuy()` / `executeSell()` 내 스냅샷 저장 연동
4. 패턴 학습 분석 서비스 (`CandlePatternLearner`)
   - 빠른 승리 케이스 추출 쿼리
   - 패턴 통계 집계
   - `fast_win_score` 계산
5. 종목검색기에 `fast_win_score` 반영
6. UI: 후보 종목에 패턴 점수 표시, 학습 결과 시각화 페이지

### 예상 작업량
- 대 (2~3일)
- 초기엔 데이터 부족 → 30~50건 쌓인 후 학습 의미있어짐

## Phase 4. AI 사용량 모니터링 화면

비용 추이 파악 및 과도한 사용 감지.

### 현황
- `ai_usage_daily` 테이블 이미 존재 (migration 0001)
- `ai.service.ts`에서 사용량 기록 중 (`recordUsageFromCompletion`)
- 현재 모델별 단가 (`defaultPricingPer1m`):

| 날짜 | 모델 | 입력 토큰 | 출력 토큰 | 호출 수 | 비용(USD) | 비용(KRW) |

**설정**
